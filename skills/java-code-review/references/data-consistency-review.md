# 数据一致性审查参考

当审查涉及事务、写入、MQ 发布、重试、幂等、补偿或并发时使用本参考。

## 事务边界

检查：

- `@Transactional` 放在 service/use-case 层，而不是 controller。
- 在保证正确性的前提下，事务范围尽量小。
- 能放到事务外的远程调用不要放在事务内。
- 回滚规则与 checked/unchecked 异常行为匹配。
- 批量写入有边界，失败行为清晰。

## 幂等

检查：

- 可重试操作具备幂等键、唯一约束或请求记录。
- MQ 消费者能处理重复消息。
- 外部回调不能重复执行同一状态迁移。
- 必要时幂等状态与业务状态原子更新。

## DB + MQ 一致性

检查代码是否使用以下任一模式：

- transactional outbox
- 本地消息表
- after-commit publish
- 可靠消息框架
- 补偿任务

风险信号：

- DB 提交成功，但 MQ 发布可能失败且无重试。
- MQ 在 DB 提交前发布成功，消费者读到缺失状态。
- 重试会发送重复消息，但消费者不幂等。

## 并发

检查：

- 唯一约束保护业务唯一性。
- 必要时状态迁移包含当前状态条件。
- 分布式锁、乐观锁或 DB 锁只在有充分理由时使用。
- 锁释放安全且超时有边界。
- 并发请求不能绕过校验。
