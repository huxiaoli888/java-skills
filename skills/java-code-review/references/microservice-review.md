# 微服务审查参考

当审查涉及 Feign/RPC、MQ、Redis/缓存、定时任务、外部系统、配置或运行行为时使用本参考。

## Feign / RPC / 外部调用

检查：

- 已配置超时，不依赖不安全默认值。
- 重试只用于幂等操作，或符合项目既有策略。
- 提供方特定错误在 client/adapter 边界映射。
- fallback/降级不会把失败业务操作静默返回为成功。
- 不记录敏感请求/响应字段。
- 除非已有项目标准，否则不把下游 DTO 直接暴露为本服务公开 API。
- 除非已有文档说明，否则不在 DB 事务内执行远程调用。

## MQ 生产者 / 消费者

检查：

- topic、tag、consumer group 和 payload 兼容性。
- 消费者能处理重复投递。
- 重试行为和最大重试处理。
- 死信或补偿责任人明确。
- 除非项目标准允许，否则消息体不复用 HTTP request/response DTO。
- DB 写入 + MQ 发布的一致性模式明确。
- 失败日志包含 message id、biz id、topic、group 和安全诊断上下文。

## Redis / 缓存 / 锁

检查：

- key 命名遵守项目约定。
- 需要 TTL 的场景已经显式配置。
- 写入路径处理缓存失效。
- 热点路径考虑缓存穿透、击穿、雪崩风险。
- 除非明确设计，否则 Redis 不作为隐藏事实源。
- 分布式锁具备超时、owner token 和安全释放。
- 加锁失败路径明确。

## 定时任务

检查：

- 任务在多实例部署下是安全的。
- 必要时具备分布式锁或分片策略。
- 重复执行是安全的。
- 失败重试和告警清晰。
- 长任务分页和批处理有边界。

## 配置

检查：

- 没有硬编码 URL、凭据、topic、端口或超时。
- 运行时配置变更有文档。
- 敏感值没有写入日志或提交到仓库。
- 默认值不会意外指向生产环境。
