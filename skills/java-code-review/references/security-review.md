# 安全审查参考

当审查涉及外部可访问 API、认证、授权、文件上传、签名、加密、SM2/SM3/SM4、token、密钥或敏感数据时使用本参考。

## 认证与授权

检查：

- 端点已被预期的认证层保护。
- 用户域数据已校验资源归属。
- 角色/权限检查发生在状态变更之前。
- 管理端或内部端点不能被普通用户调用。

## 输入与注入

检查：

- 外部输入已校验。
- SQL 使用 mapper 参数或预编译语句，不使用字符串拼接。
- 文件路径已规范化，并限制在允许目录内。
- 对外调用 URL 不会触发 SSRF。
- 文件上传检查大小、扩展名、content type、存储路径和授权。

## 敏感数据

检查：

- 日志不包含密码、token、手机号、身份证号、密钥、签名或明文敏感数据。
- API 响应不暴露内部错误、密钥或过量用户数据。
- 项目要求静态加密的敏感数据已经加密。
- 测试 fixture 不包含生产密钥。

## 签名、加密与防重放

检查：

- 信任业务字段前已完成签名校验。
- 时间戳和 nonce/replay window 已校验。
- 签名 canonicalization 顺序稳定且兼容。
- SM2 私钥或 SM4 密钥没有写入日志、代码、镜像或明文配置。
- 软密钥文件的使用没有扩大密钥暴露面。
- HSM/密码机集成不允许未授权签名或解密调用。
- 数字信封变更保持加密、签名和密钥交换顺序正确。

## 密码审查注意

不要建议自定义密码算法或临时协议变更。遇到不清楚的密码行为，应标注低置信度，并建议安全负责人复核。
