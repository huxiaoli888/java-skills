# JVM 事故参考

用于 OOM、Full GC、CPU 高、死锁、线程耗尽、内存泄漏和 JVM 层服务降级。

## 需要采集的证据

- JVM 进程 ID。
- GC 日志或 GC 指标。
- 堆内存和非堆内存使用情况。
- 线程转储，最好采集多次样本。
- CPU 高时的热点线程。
- 近期发布或配置变更。
- 流量和请求类型变化。

## 常用命令

```powershell
jps -lv
jcmd <pid> VM.version
jcmd <pid> GC.heap_info
jcmd <pid> Thread.print
jcmd <pid> GC.class_histogram
```

CPU 高时：

1. 确认 Java 进程 ID。
2. 使用操作系统工具确认热点原生线程 ID。
3. 将线程 ID 转为十六进制。
4. 在线程转储中匹配 `nid=0x...`。

## 常见原因

| 现象 | 可能原因 |
| --- | --- |
| OOM | 无界集合、缓存膨胀、大响应对象、内存泄漏、待处理任务过多 |
| Full GC | 堆压力、老年代增长、分配突增 |
| CPU 高 | 热循环、重试风暴、序列化、正则、压缩、密码计算热点 |
| 线程阻塞 | 外部调用无超时、DB 锁、同步块、线程池耗尽 |
| 死锁 | 嵌套锁、DB/JVM 锁混用、不安全的加锁顺序 |

## 止血

- 如果与近期版本相关，优先回滚。
- 削减流量或关闭热点功能。
- 暂停导致内存分配或 CPU 突增的调度任务/消费者。
- 只有在已采集证据且重启安全，或影响要求立即恢复时，才执行重启。

## 恢复验证

- 错误率下降。
- GC 频率和暂停时间恢复正常。
- 线程池活跃数和队列指标恢复。
- CPU/内存回到预期范围。
