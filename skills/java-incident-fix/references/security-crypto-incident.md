# 安全与密码事故参考

用于鉴权绕过、敏感数据暴露、token/key 泄漏、签名失败、重放攻击、SM2/SM3/SM4 问题、数字信封问题、软密钥暴露或 HSM/密码机事故。

## 即时动作

- 保留证据。
- 如果暴露仍在发生，禁用受影响端点或功能。
- 吊销或轮换已泄露的凭据、token、证书或密钥。
- 确认恶意客户端后进行阻断。
- 通知安全/合规负责人。
- 不要把原始密钥或敏感日志写入文档。

## 需要采集的证据

- 访问日志和 trace id。
- 受影响用户/租户。
- 暴露字段或密钥范围。
- 鉴权/权限决策日志。
- 签名验签失败记录。
- timestamp/nonce/replay 日志。
- key id、证书 id 或 HSM key handle，不记录原始密钥。
- 近期鉴权、密码、配置或网关变更。

## 密码流程检查

- 信任业务字段前已经完成签名校验。
- 状态变更前已经校验时间戳和防重放编号。
- 重放窗口有明确边界。
- 签名 canonicalization 顺序与客户端一致。
- SM2 私钥和 SM4 密钥没有写入日志、提交到仓库、打进镜像或明文存储在配置中。
- 数字信封流程保持加密、签名和密钥交换顺序正确。
- HSM/密码机访问控制能阻止未授权签名或解密。

## 密钥泄漏响应

- 确认密钥类型和影响范围。
- 禁用或轮换密钥。
- 必要时重新签发证书。
- 在可行且必要时重新加密受影响数据。
- 审计泄露密钥的所有使用记录。
- 记录业务和合规影响。

## 恢复验证

- 未授权访问已停止。
- 新凭据/密钥已经生效。
- 旧凭据/密钥已被拒绝。
- 日志中不再出现进一步重放或签名绕过。
- 受影响数据范围已经明确。
